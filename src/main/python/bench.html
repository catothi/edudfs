2 · Sweet spots


Run a sweep with one storage preset, switch the preset and run it again - each preset becomes its own
line (“× best” compares the shapes). Files: every extra file costs a listing entry, a footer read and requests -
the curve only rises. Row groups: U-shaped - too big and nothing can be skipped, too small and the overhead per
row group (footer entries, requests, pages) dominates.

Why not one huge file? Here 1 file = 5 MB. In production a file is also the unit of parallel
work (one task per file or row group), so the sweet spot is files of 128 MB - 1 GB with row groups of ~128 MB - big enough
that a request costing milliseconds is worth it, small enough to skip and to spread over workers. Try the query
“Total revenue” (nothing to skip): the row group curve flattens, only the overhead remains.
